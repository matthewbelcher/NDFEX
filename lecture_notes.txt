Protocols
Agreed upon conventions for communicating
In the internet world they are published as RFCs
For example, RFC793 specifies how TCP works
https://www.rfc-editor.org/rfc/rfc793
The whole point of protocols is to allow anyone who follows the protocol to talk to
anyone else who does - if you control everything you can do whatever you want

Layer 2 (Data link layer, MAC)
Officially called data link but everyone calls it L2 or MAC
Mac means “medium access control”
That is, it is a protocol that specifies when a computer can manipulate the
“medium,” i.e. copper wires, fiber optic cables, or wireless frequencies

Layer 2 Switching
Switches maintain a table of MAC -> Port internally which allows them to send
local packets to the right place
Switches can also use the vlan tag to send packets (e.g. anything with vlan tag
100 goes to port 9)
Switches can also mirror traffic on ports to other ports

Switch modes
Store and forward vs cut-through
S&F can do error checking but it is slower and requires the switch to buffer
packets
Cut-through can deliver broken packets but it is fastest

Retransmission
What happens if there is a sequence number gap?
When the receiver detects the gap, it sends another ack with the ack seq of the
last received sequence
When sender sees 3 duplicate acknowledgements it begins retransmission
Then it will resend that packet

Congestion window
Negotiated when the connection is established
Grows based on packet receive
If in-flight bytes > window size we won’t send

HFT and TCP
Mostly TCP’s features are just problems for us
